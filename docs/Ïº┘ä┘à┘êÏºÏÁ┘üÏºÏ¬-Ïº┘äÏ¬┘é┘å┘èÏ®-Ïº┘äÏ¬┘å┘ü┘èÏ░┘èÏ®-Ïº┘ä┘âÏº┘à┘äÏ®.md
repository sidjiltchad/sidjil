# المواصفات التقنية التنفيذية — سِجِل / SIDJIL

> الاسم السابق للمشروع: أرشيفنا / Archifouna (أُعيدت التسمية في 2026-10-01؛ انظر docs/adr/002-rename-archifouna-to-sidjil.md).

**الإصدار:** 1.0
**نوع المشروع:** أرشيف تاريخي رقمي ثنائي اللغة
**النطاق الأساسي:** تاريخ تشاد
**اللغات:** العربية والفرنسية
**البنية المقترحة:** Cloudflare + D1 + R2

> حُفظت هذه الوثيقة كما وردت من يعقوب بتاريخ 2026-10-01، وهي المرجع المعتمد
> لمواصفات المنصة. أي تعارض بينها وبين وثائق أخرى يُحسم لصالح هذه النسخة
> ما لم يقرر يعقوب خلاف ذلك صراحة.

---

## 1. الغرض من الوثيقة

تحدد هذه الوثيقة المواصفات التقنية اللازمة لبناء منصة سِجِل – SIDJIL بصورة قابلة للتنفيذ مباشرة.

يجب أن تسمح المنصة بـ:

- رفع الوثائق والكتب والمخطوطات والصور والخرائط.
- حفظ الملفات الأصلية دون تعديل.
- حفظ نسخ مشتقة من الصور مثل الترميم والتحسين والتلوين.
- فهرسة المواد بصورة علمية.
- البحث بالعربية والفرنسية.
- استخراج النصوص من الوثائق.
- ترجمة النصوص الفرنسية إلى العربية.
- مراجعة الترجمات قبل اعتمادها.
- توثيق المصدر والمرجع الأرشيفي.
- ربط المواد بالأشخاص والأماكن والمصادر والموضوعات.
- توفير روابط دائمة يمكن الاستشهاد بها.
- إدارة المحتوى من لوحة إدارة خاصة.

## 2. المبادئ المعمارية

يجب الفصل بين ثلاثة أنواع من البيانات:

### أ. البيانات الوصفية Metadata

مثل: العنوان، التاريخ، المصدر، المكان، الكلمات المفتاحية، الأشخاص، حالة الترجمة.

تخزن في: Cloudflare D1

### ب. الملفات

مثل: PDF، DOCX، الصور الأصلية، الصور المرممة، الخرائط.

تخزن في: Cloudflare R2

### ج. المحتوى النصي القابل للبحث

مثل: التفريغ الفرنسي، الترجمة العربية، الوصف، العناوين.

يخزن في D1 ويفهرس بواسطة FTS5 للبحث النصي.

## 4. التقنية المقترحة

> **ملاحظة تنفيذية (2026-10-01 — ADR-001):** هذا البند كان **اقتراحًا تقنيًا غير ملزم**.
> البنية **المنفذة فعلًا** هي: **Vanilla HTML/CSS/JavaScript + Cloudflare Workers + D1 + R2**
> (بلا أطر عمل، بلا خطوة بناء)، مع مصادقة إدارية بجلسات PBKDF2 عبر WebCrypto.
> التفاصيل في `docs/adr/001-vanilla-stack.md`. المعيار الحاكم هو تحقيق الوظائف
> والمعايير المنهجية والأمنية والأدائية، لا استخدام إطار بعينه.

### البنية المقترحة أصلًا (غير ملزمة)

#### Frontend

Astro + TypeScript — سريع، ممتاز للمواقع التي يغلب عليها المحتوى، مناسب لـ SEO، يعمل على Cloudflare، يسمح بمكونات تفاعلية عند الحاجة فقط.

للتنسيق: Tailwind CSS (أو CSS عادي لتقليل الاعتماديات).

#### Backend

Cloudflare Workers مع Hono لبناء REST API خفيف.

### البنية المنفذة فعلًا (المعتمدة — 2026-10-01)

- **Frontend:** HTML/CSS/JavaScript خالص (Vanilla) — صفحات مولّدة خادوميًا في
  `src/views.js`، ولوحة إدارة في `src/admin-views.js` + `public/admin.js`.
- **Backend:** Cloudflare Workers بلا إطار (`src/index.js` موجّه بسيط).
- **قاعدة البيانات:** Cloudflare D1 / SQLite (كما هي).
- **تخزين الملفات:** Cloudflare R2 (كما هو).
- **التحقق من المدخلات:** تحقق يدوي صارم في `src/admin-api.js` (بدل Zod).
- **المصادقة الإدارية:** جلسات PBKDF2 عبر WebCrypto + كوكي HttpOnly
  (`src/lib/auth.js`) — بدل Cloudflare Access. وبما أن المصادقة كوكيز جلسات،
  طُبّقت حماية CSRF فعلية على كل الطلبات المعدِّلة (`X-CSRF-Token`).

### قاعدة البيانات

Cloudflare D1 / SQLite

### تخزين الملفات

Cloudflare R2

### التحقق من المدخلات

Zod (مقترح أصلًا) — **المنفذ فعلًا:** تحقق يدوي صارم في `src/admin-api.js`.

### PDF Viewer

PDF.js — **المنفذ فعلًا:** PDF.js 4.2.67 **كمكتبة وظيفية فقط**
(`public/vendor/pdfjs/`)، لا كإطار عمل.

### المصادقة الإدارية

الخيار المفضل (أصلًا): Cloudflare Access — بحيث لا يمكن الوصول إلى "/admin" إلا للحسابات المصرح لها.

**المنفذ فعلًا:** جلسات PBKDF2 + CSRF (انظر أعلاه).

## 6. معرفات المواد

لكل مادة رقمان:

- **المعرف الداخلي** INTEGER مثل: 1532
- **الرقم الأرشيفي العام** مثل: ARC-TD-DOC-0001532

أنواع البادئات: DOC / IMG / MSS / MAP / BOOK / PRESS / LETTER / TEXT

أمثلة: ARC-TD-IMG-000014، ARC-TD-DOC-001357، ARC-TD-MSS-000042

هذا الرقم: لا يتغير، يُستخدم في الاستشهاد، يظهر للمستخدم، لا يعتمد على عنوان المادة.

## 10. قاعدة مهمة للأصول

أي ملف `role = original` يجب أن يكون `is_immutable = 1`، ولا يسمح التطبيق بإعادة الكتابة فوقه. الاستبدال يكون بملف جديد مع الاحتفاظ بالسابق أو نقله إلى حالة `superseded` — لا `overwrite` على الكائن الأصلي أبدًا.

## 14. الفرق بين raw_text و corrected_text

- `raw_text`: النص المستخرج آليًا بواسطة OCR.
- `corrected_text`: النص بعد المراجعة البشرية.
- الموقع العام يعرض `corrected_text` إن وجد، وإلا `raw_text` مع تنبيه أنه غير مراجع.

## 34-35. البحث النصي — FTS5

```sql
CREATE VIRTUAL TABLE search_fts USING fts5(
    material_id UNINDEXED,
    title_ar, title_original,
    description_ar, description_fr,
    transcription_text, translation_ar,
    people_text, places_text, tags_text,
    normalized_text,
    tokenize='unicode61 remove_diacritics 2'
);
```

لا JOIN في كل بحث — عند إنشاء/تعديل مادة أو إضافة ترجمة/تفريغ/شخص/مكان/Tag يُعاد بناء سجل البحث الخاص بالمادة عبر `rebuildSearchIndex(materialId)`.

## 38-44. بنية R2

- اسم Bucket: `sidjil-assets` — يظل Private، لا وصول مباشر للأصول من الإنترنت، الوصول عبر Worker.
- المفاتيح:
  - الأصل: `originals/ARC-TD-IMG-000042/<sha256>/original.jpg`
  - المشتقات: `derivatives/ARC-TD-IMG-000042/{restored,enhanced,colorized,annotated}/uuid.jpg`
  - المعاينات: `previews/ARC-TD-DOC-000412/page-0001.webp`
  - المصغرات: `thumbnails/ARC-TD-IMG-000042/{320,640}.webp`
  - النسخ الاحتياطية: `backups/metadata/2026/10/2026-10-01.json`
- قاعدة عدم overwrite: أي مسار تحت `originals/` لا يُعاد استخدامه أبدًا — يُستخدم UUID أو SHA-256 ضمن المسار.

## 90-96. سير عمل الترجمة

رفع → OCR → نص خام → مراجعة التفريغ → اعتماد التفريغ → ترجمة آلية → مراجعة بشرية → اعتماد → نشر.

قواعد: لا ترجمة من OCR رديء قبل التصحيح. Context ثابت لمحرك الترجمة (مترجم متخصص في الوثائق التاريخية الفرنسية لتشاد...). تقسيم النص إلى Segments مع الحفاظ على الترتيب والصفحات والهوامش. فحوص جودة آلية قبل الاعتماد (الأرقام، التواريخ، الأسماء، الفقرات المفقودة/المكررة). القاموس يُستدعى عبر `getRelevantGlossaryTerms(document)` لا كاملًا. تحرير القاموس في `/admin/glossary`.

## 97-101. سير عمل الصور

`Original → {Restored, Enhanced, Colorized, Annotated}` — علاقة اشتقاق لا استبدال. كل نسخة تسجل: نوع المعالجة، تاريخها، الأداة، النموذج، الملاحظات، هل تتضمن استنتاجًا تاريخيًا. تنبيه التلوين عند `historical_inference=1`: «هذه نسخة معالجة أو ملونة تقديريًا...». زر «عرض الأصل» ظاهر دائمًا. المصغرات في MVP تُنشأ في المتصفح عبر Canvas API (WebP 320/640)، وغلاف PDF عبر PDF.js قبل الرفع.

## 111-120. الأمن والملفات

- كل `/admin/*` وAPI الإدارية محمية.
- أنواع MVP المقبولة: pdf, docx, jpeg, png, webp, tiff — مع فحص MIME والامتداد وmagic bytes.
- أسماء الملفات: Key آمن مولّد (UUID) لا اسم المستخدم؛ الاسم الأصلي في قاعدة البيانات.
- CORS: Same-Origin، لا CORS مفتوح للإدارة. CSRF للعمليات المعدلة عند استخدام الكوكيز.
- Rate Limiting على `/search` و`/files/download`.
- Cache: صفحات المواد `public, max-age=300`، المصغرات طويل، API الإدارة `no-store`.
- SHA-256 لكل ملف أصلي في `files.sha256`، يظهر في لوحة الإدارة (وللعامة في البيانات التقنية إن أُريد).
- الحذف منطقي؛ ملفات Original لا تُحذف من R2 تلقائيًا — الحذف المادي إجراء منفصل بصلاحية عليا.
