# دليل التشغيل والنشر — سِجِل

> الاسم السابق للمشروع: أرشيفنا / Archifouna (أُعيدت التسمية في 2026-10-01).

## 1) المتطلبات

- Node.js 18+
- حساب Cloudflare (للنشر الإنتاجي فقط — التطوير المحلي لا يحتاجه)

## 2) التشغيل المحلي

```bash
cd archifouna
npm install

# إنشاء قاعدة D1 المحلية وتطبيق المخطط
npx wrangler d1 execute archifouna-db --local --file=migrations/0001_init.sql

# توليد بصمة كلمة مرور المدير
node scripts/hash-password.js 'اختر-كلمة-مرور-قوية-هنا'
```

انسخ `.dev.vars.example` إلى `.dev.vars` وضع فيه ناتج الأمر السابق:

```
ADMIN_PASSWORD_HASH=<الناتج>
```

ثم:

```bash
npx wrangler dev --port 8787
```

- الواجهة العامة: http://127.0.0.1:8787/
- لوحة الإدارة: http://127.0.0.1:8787/admin (الدخول: admin + كلمة المرور)

### تجهيز بيانات العرض

يحتاج السكربت ملفات حقيقية موجودة في بيئة التطوير الأصلية
(نصوص وثائق GG AEF 5D 269 في `/tmp/college/` وصور أبشة في
`~/workspace/tchad-corpus/anom/images/`). بدونهما سيفشل الرفع —
يمكنك تجهيز بياناتك الخاصة من لوحة الإدارة بدلًا منه:

```bash
ADMIN_PASSWORD='<كلمة-مرور-المدير>' node scripts/seed-demo.mjs
```

## 3) النشر إلى Cloudflare (الإنتاج)

```bash
# 1) إنشاء قاعدة D1 للإنتاج
npx wrangler d1 create sidjil-prod
# انسخ database_id الناتج إلى wrangler.toml مكان القيمة الصفرية

# 2) تطبيق المخطط على الإنتاج
npx wrangler d1 execute sidjil-prod --remote --file=migrations/0001_init.sql

# 3) إنشاء حاوية R2 للإنتاج
npx wrangler r2 bucket create sidjil-assets

# 4) كلمة مرور المدير كسرّ (لا توضع في الكود أبدًا)
node scripts/hash-password.js 'كلمة-مرور-الإنتاج-القوية'
npx wrangler secret put ADMIN_PASSWORD_HASH
# الصق الناتج عندما يُطلب

# 5) النشر
npx wrangler deploy
```

## 4) النسخ الاحتياطي والاستقلالية

- **تصدير JSON**: من لوحة الإدارة `/admin/backup` — يصدّر كل الجداول.
- **استعادة**: أعد تطبيق `migrations/0001_init.sql` على قاعدة فارغة ثم
  استورد ملف JSON من صفحة النسخ الاحتياطي.
- **ملفات R2**: تُنسخ بأداة `wrangler r2 object` أو من لوحة Cloudflare.
- لا ارتباط بمزود خارجي: لا CDN، لا أطر عمل، لا خدمات تتبع.

## 5) ملاحظات أمنية

- كلمات المرور تُخزَّن PBKDF2-SHA256 (600,000 تكرار) + ملح عشوائي.
- الجلسات 12 ساعة، كوكي HttpOnly + SameSite=Lax + Secure في الإنتاج.
- كل كتابة إدارية مسجلة في سجل التدقيق (`audit_log`).
- غيّر كلمة مرور `admin` الافتراضية فور النشر.
- لا تضع `ADMIN_PASSWORD_HASH` في `wrangler.toml` أو في أي ملف يُرفع.

## 6) استكشاف الأخطاء

| العرض | السبب المحتمل |
|---|---|
| `Address already in use :8787` | عملية wrangler/workerd قديمة ما زالت تعمل — أوقفها ثم أعد التشغيل |
| صفحة بيضاء بلا تنسيق | تأكد أن `[assets] directory = "./public"` وأن `wrangler dev` يعمل من جذر المشروع |
| فشل الدخول للإدارة | تأكد من `ADMIN_PASSWORD_HASH` في `.dev.vars` (محليًا) أو `wrangler secret` (إنتاج) |
| البحث لا يجد نتائج عربية | أعد بناء فهرس FTS: يُبنى تلقائيًا عند إدخال المواد عبر API |
