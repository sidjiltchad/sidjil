## 1. نظرة عامة ونطاق النسخة الأولى (MVP)

### 1.1 ما هو سِجِل

منصة رقمية مستقلة لحفظ وفهرسة وإتاحة المصادر المتعلقة بتاريخ تشاد: الوثائق، الكتب والدراسات، المخطوطات، الصور التاريخية، الخرائط، الصحافة، المراسلات، والنصوص والمقتطفات. جوهر المشروع خمس وظائف مترابطة: **الحفظ، التوثيق، البحث، الترجمة، الاستعادة الرقمية**.

### 1.2 نطاق V1 (ما يُبنى الآن)

| المكوّن | الوصف |
|---|---|
| الواجهة العامة | الرئيسية، الأرشيف، البحث، البحث المتقدم، التصنيفات، الأماكن، الشخصيات، المصادر، المجموعات، صفحة المادة، حول سِجِل، منهجية التوثيق والترميم والترجمة |
| صفحة المادة | بيانات تعريف كاملة، عرض/معاينة/تنزيل الملفات، التفريغ النصي، الترجمة العربية، مواد ذات صلة، استشهاد جاهز مع زر نسخ، رابط دائم |
| البحث | بحث نصي كامل عربي/فرنسي (FTS5) + بحث متقدم متعدد الحقول |
| الترجمة | طبقات نص مستقلة (أصل/تفريغ/ترجمة) مع خمس حالات سير عمل ظاهرة للزائر |
| الصور | الأصل + المشتقات (ترميم/تحسين/تلوين/تعليق/قص) مع أداة مقارنة قبل/بعد وبيان معالجة إلزامي |
| لوحة إدارة واحدة | إضافة/تعديل/حذف/إخفاء المواد، رفع الملفات، إدارة نسخ الصور، إدارة الترجمات، إدارة الأشخاص/الأماكن/المصادر/الوسوم/المجموعات/القاموس، مراقبة الحالة، النسخ الاحتياطي |
| اللغتان | العربية (افتراضية) والفرنسية للواجهة؛ لا يُشترط ترجمة كل المواد |
| SEO | عناوين ووصف و Open Graph لكل مادة، روابط دائمة، sitemap |

### 1.3 خارج النطاق في V1 (صراحةً، لا تُبنى الآن)

- حسابات للزوار، تعليقات، إعجابات، منتدى، شبكة اجتماعية.
- تطبيق هاتف، نظام دفع، صلاحيات إدارية معقدة (مدير واحد يكفي).
- ذكاء اصطناعي يعمل تلقائيًا على كل وثيقة (OCR وترجمة آلية جماعية).
- خرائط تفاعلية، خط زمني تفاعلي، API عام للباحثين (يوجد JSON داخلي للواجهة فقط)، حسابات مساهمين.

## 2. البنية التقنية

### 2.1 رسم التدفق

```
المستخدم (متصفح)
   ↓ HTTPS
sidjil.org
   ↓
Cloudflare Worker (src/index.js — الموجّه الرئيسي)
   ├── D1 (قاعدة بيانات SQLite مُدارة)
   │     الفهرسة، النصوص، العلاقات، الجلسات، سجل التدقيق
   │
   └── R2 (حاوية sidjil-assets)
         الملفات الأصلية والمشتقة والمصغرات والنسخ الاحتياطية
```

ترتيب التوجيه داخل الـ Worker (حسب `docs/API.md`):
`routeAdminApi` ← `routeApi` ← مسارات `/admin/*` (تحقق جلسة ثم `renderAdmin`) ← `renderPublic` (أي مسار آخر).

### 2.2 سبب الاختيار

- **Worker**: بلا خادم يُدار، استجابة من أقرب نقطة Edge، تكلفة تشغيل قريبة من الصفر للحجم المتوقع.
- **D1**: قاعدة علائقية (SQLite) تكفي لنموذج البيانات العلائقي الغني (مواد ↔ أشخاص ↔ أماكن ↔ مصادر)، وتدعم FTS5 للبحث العربي/الفرنسي، وتُدار بالترحيلات (`wrangler d1 migrations apply`).
- **R2**: تخزين كائنات بلا رسوم إخراج (egress) — حاسم لأرشيف يقدّم ملفات PDF وصورًا كبيرة للجمهور. **القاعدة الصارمة: لا توضع ملفات PDF أو صور كبيرة داخل قاعدة البيانات أبدًا**؛ D1 للبيانات الوصفية والنصوص فقط.

### 2.3 وضع التطوير المحلي

- `wrangler dev` مع ربط محلي لـ D1 وR2 (miniflare).
- الأسرار المحلية في `.dev.vars` (لا تُرفع إلى المستودع): `ADMIN_PASSWORD_HASH` كبديل لإنشاء المدير الأول عندما يكون جدول `admin_users` فارغًا.
- لا أسرار في الكود المصدري إطلاقًا.

## 3. نموذج البيانات

المصدر الملزم حرفيًا: `migrations/0001_init.sql`. أسماء الجداول والأعمدة نهائية ولا تُغيَّر. أدناه شرح كل جدول: غرضه وأعمدته المهمة وعلاقاته.

### 3.1 جداول الفهرس المرجعية

| الجدول | الغرض | الأعمدة المهمة | العلاقات |
|---|---|---|---|
| `counters` | عدّادات الترقيم الأرشيفي الذرية | `type_code` (PK: DOC/BOK/MSS/IMG/MAP/PRS/COR/EXC)، `next_num` | تُزاد ذريًا عند إنشاء مادة |
| `sources` | المؤسسات المصدرية (ANOM، Gallica، ECPAD...) | `name` (الأصلي)، `name_ar`، `kind` (archive/library/museum/private/web/press)، `website` | `materials.source_id` ← هنا |
| `people` | الشخصيات | `name_ar`، `name_orig`، `bio`، `birth_year`، `death_year`، `identity_confidence` (confirmed/probable/unknown) | `material_people` |
| `places` | الأماكن | `name_ar`، `name_orig`، `region` (وداي، كانم...)، `kind` (city/region/country/site)، `lat`، `lng`، `place_confidence` (confirmed/probable/unknown) | `materials.place_id` + `material_places` |
| `tags` | الكلمات المفتاحية | `name_ar` (UNIQUE)، `name_orig` | `material_tags` |
| `collections` | المجموعات الموضوعية المختارة | `title_ar`، `title_fr`، `cover_material_id`، `sort_order` | `material_collections` |
| `glossary` | قاموس الترجمة المتخصص | `term_orig`، `term_ar` (UNIQUE معًا)، `domain` | يُدار من لوحة الإدارة |

### 3.2 الجدول المركزي: `materials`

السجل الأساسي لكل مادة. أهم الأعمدة:

- **الهوية:** `id`، `ark` (UNIQUE — الرقم الأرشيفي الثابت، انظر §4)، `type` (document/book/manuscript/image/map/press/correspondence/excerpt).
- **العناوين والوصف:** `title_ar` (إلزامي)، `title_orig`، `description`.
- **الزمن:** `year`، `date_text` (عرض حر مثل «6 ديسمبر 1951»)، `date_confidence` (confirmed/approximate/probable/unknown).
- **المسؤولية:** `author`، `photographer`، `language` (fr/ar/...)، `place_id` + `place_confidence`.
- **المصدر:** `source_id`، `archive_ref` (مثل `5D 269`)، `source_url`، `rights`.
- **المحتوى النصي:** `full_text` (النص المنظّم للعرض والبحث)، `search_blob` (نص مطبّع يُبنى برمجيًا للفهرسة).
- **حالات سير العمل:** `transcription_status` (none/auto/corrected)، `translation_status` (none/machine/in_review/reviewed/approved)، `publish_status` (draft/published/hidden).
- **التشغيل:** `views`، `created_at`، `updated_at`.

**البحث النصي:** جدول افتراضي `materials_fts` (FTS5, `tokenize='unicode61'`) بأعمدة `ark` (UNINDEXED)، `title`، `body`. يُدار حصريًا من طبقة التطبيق عبر `rebuildSearchBlob()` — حذف ثم إدخال الصف عند كل تعديل.

### 3.3 الملفات والصور

| الجدول | الغرض | الأعمدة المهمة | العلاقات |
|---|---|---|---|
| `files` | كل الملفات (المحتوى في R2، البيانات الوصفية هنا) | `material_id` (CASCADE)، `kind` (original/attachment/thumbnail)، `filename`، `mime`، `size`، `sha256` (البصمة الرقمية)، `r2_key` (UNIQUE) | `image_versions.file_id` ← هنا |
| `image_versions` | نسخ الصور: الأصل والمشتقات | `material_id` (CASCADE)، `version_type` (original/restored/enhanced/colorized/annotated/cropped)، `file_id` (CASCADE)، `process_note` (بيان المعالجة الظاهر للزائر)، `sort_order` | تربط المشتق بالأصل عبر `material_id` |
| `transcriptions` | طبقات التفريغ النصي (لا يستبدل أحدهما الآخر) | `material_id` (CASCADE)، `layer` (auto/manual)، `lang`، `text` | — |
| `translations` | الترجمات مع حالة سير العمل | `material_id` (CASCADE)، `source_lang`، `target_lang` (افتراضي ar)، `text`، `status` (machine/in_review/reviewed/approved)، `translator` | — |

### 3.4 جداول الربط

- `material_people` (material_id, person_id, role) — PK مركبة.
- `material_places` (material_id, place_id, relation) — PK مركبة.
- `material_tags` (material_id, tag_id) — PK مركبة.
- `material_collections` (material_id, collection_id, sort_order) — PK مركبة.
- `material_relations` (id, material_a, material_b, relation, note) — علاقات مادة↔مادة، UNIQUE على (a,b).

### 3.5 الإدارة والأمن

| الجدول | الغرض | الأعمدة المهمة |
|---|---|---|
| `admin_users` | حسابات الإدارة | `username` (UNIQUE)، `password_hash` (صيغة `pbkdf2$iter$salt$hash` بـ base64) |
| `sessions` | الجلسات | `token` (PK)، `user_id` (CASCADE)، `expires_at` (12 ساعة) |
| `audit_log` | سجل العمليات الإدارية | `user_id`، `action` (مثل `material.create`)، `target`، `detail`، `ip`، فهرس على `created_at` DESC |

## 4. نظام الترقيم الأرشيفي

### 4.1 الصيغة

```
ARC-TD-{CODE}-NNNNNN
```

| النوع (type) | الرمز (CODE) | مثال |
|---|---|---|
| document (وثيقة) | DOC | ARC-TD-DOC-000001 |
| book (كتاب/دراسة) | BOK | ARC-TD-BOK-000002 |
| manuscript (مخطوط) | MSS | ARC-TD-MSS-000003 |
| image (صورة) | IMG | ARC-TD-IMG-000152 |
| map (خريطة) | MAP | ARC-TD-MAP-000004 |
| press (صحافة) | PRS | ARC-TD-PRS-000005 |
| correspondence (مراسلة) | COR | ARC-TD-COR-000006 |
| excerpt (نص/مقتطف) | EXC | ARC-TD-EXC-000007 |

### 4.2 قواعد الثبات (ملزمة)

1. يُولَّد الرقم تلقائيًا عند الإنشاء عبر `nextArk(db, type)` بزيادة ذرية في جدول `counters` (معاملة `batch` واحدة تشمل العدّاد + المادة + صف FTS).
2. **الرقم ثابت دائمًا** — لا يتغير بتغيّر العنوان أو النوع أو أي حقل آخر.
3. العمود `ark` عليه قيد `UNIQUE` وفهرس مخصص؛ وهو المعرّف الظاهر في الروابط الدائمة والاستشهادات.
4. لا يُعاد استخدام رقم محذوف أبدًا (العدّاد أحادي الاتجاه).

## 5. تنظيم R2

الحاوية: `sidjil-assets`. المبدأ الأعلى: **الأصل لا يُستبدل أبدًا** — أي نسخة جديدة = مفتاح جديد.

### 5.1 هيكل المفاتيح

```
originals/
  documents/ARC-TD-DOC-000001/<sha8>-<safe-name>.pdf
  books/ARC-TD-BOK-000002/<sha8>-<safe-name>.pdf
  manuscripts/ARC-TD-MSS-000003/<sha8>-<safe-name>.pdf
  images/ARC-TD-IMG-000152/<sha8>-original.jpg
  maps/ARC-TD-MAP-000004/<sha8>-<safe-name>.jpg
  press/ARC-TD-PRS-000005/<sha8>-<safe-name>.pdf
  correspondence/ARC-TD-COR-000006/<sha8>-<safe-name>.pdf
  excerpts/ARC-TD-EXC-000007/<sha8>-<safe-name>.pdf
derived/
  images/ARC-TD-IMG-000152/restored-<sha8>.jpg
  images/ARC-TD-IMG-000152/colorized-<sha8>.jpg
thumbnails/
  ARC-TD-IMG-000152/thumb-480.jpg
exports/
  backup-2026-10-01/SIDJIL.json
  backup-2026-10-01/manifest.csv
```

الدليل النوعي تحت `originals/` يُشتق من `TYPE_DIRS` في `lib/db.js` (documents/books/manuscripts/images/maps/press/correspondence/excerpts).

### 5.2 قواعد حماية الأصل والمشتقات

1. **الأصل** يُرفع مرة واحدة إلى `originals/...` ولا يُكتب فوقه أبدًا؛ تُحسب بصمته `sha256` عند الرفع (عبر `crypto.subtle.digest`) وتُحفظ في جدول `files`، وتدخل أول 8 خانات منها في اسم المفتاح.
2. **المشتقات**: كل ترميم/تحسين/تلوين/تعليق/قص ملفٌ جديد في `derived/...` + صف جديد في `image_versions` مرتبط بالأصل عبر `material_id`، مع بيان معالجة `process_note` إلزامي الظهور للزائر.
3. **المصغرات** في `thumbnails/...` تُولَّد عند العرض (أو عند الرفع لاحقًا).
4. **الحذف**: حذف مادة يحذف صفوف `files` المرتبطة **ومفاتيح R2 المقابلة** (ينفذها `admin-api`).
5. **التقديم العام**: `GET /file/:id` يقرأ `r2_key` من D1 ثم يبث من R2 مع `Content-Type` الصحيح؛ `?download=1` يضيف `Content-Disposition: attachment`. **لا تُكشف مفاتيح R2 الخام للزائر أبدًا** — فقط `/file/:id`.
6. **النسخ الاحتياطي**: `exports/backup-YYYY-MM-DD/` يحوي تفريغ قاعدة البيانات + `manifest.csv` (كل `r2_key` مع `sha256` والحجم) للتحقق من سلامة النسخة.

## 7. البحث

### 7.1 الحقول المشمولة في الفهرسة

يُبنى `search_blob` (ويُفهرس في `materials_fts`) من: العنوان العربي، العنوان الأصلي، الوصف، النص الكامل (`full_text`)، نصوص التفريغ (الآلي والمصحح)، نصوص الترجمات، أسماء الأشخاص المرتبطين، أسماء الأماكن، الكلمات المفتاحية، اسم المصدر، المرجع الأرشيفي. وهذا يحقق متطلب التصور: البحث في «التعليم العربي في أبشة» يجد وثيقة فرنسية ورد فيها `enseignement arabe à Abéché` داخل نصها أو ترجمتها حتى لو غاب التعبير عن عنوانها.

### 7.2 التطبيع العربي/الفرنسي (`normalizeText`)

- إزالة التشكيل (`\u064B-\u065F\u0670`) والتطويل (`\u0640`).
- توحيد الهمزات `أإآٱ`←`ا`، `ة`←`ه`، `ى`←`ي`، `ؤ`←`و`، `ئ`←`ي`.
- فرنسي: تصغير + إزالة علامات التشكيل عبر `normalize('NFD')`.
- تقليص المسافات الزائدة.

النتيجة: بحث جزئي متسامح مع اختلافات الإملاء والتشكيل في اللغتين.

### 7.3 FTS5

- جدول `materials_fts` بتقنية `unicode61`.
- الاستعلام: كل رمز بعد التطبيع يُلحق به `*` (بحث بادئة/جزئي)، والصيغة `"t1"* "t2"*` تبحث في العنوان والمتن معًا.
- الترتيب بـ `bm25(materials_fts, 8.0, 1.0)` — ترجيح تطابق العنوان 8 أضعاف المتن.
- النتائج تتضمن `snippet` بتمييز `<mark>` حول التطابق (30 رمزًا سياقيًا).

### 7.4 البحث المتقدم

`advancedSearch` هي نفس دالة `searchMaterials` — الواجهة تجمع الحقول فقط. المعاملات: `q`، `type`، `fromYear`/`toYear`، `region` (يُطابق `places.region`)، `lang`، `personId`، `tagId`، `sourceId`، `collectionId`، `placeId`، `translationStatus`. تُبنى الفلاتر كشروط `WHERE` إضافية مع `JOIN` على الجداول الوسيطة عند الحاجة، وقابلة للجمع (مثال التصور: «جميع الوثائق الفرنسية المتعلقة بأبشة بين 1900 و1920 والمتصلة بالتعليم»).

## 8. الترجمة

### 8.1 طبقات النص الأربع (مستقلة، لا يستبدل أحدها الآخر)

```
الصورة/الملف الأصلي
   ↓
النص المستخرج آليًا  (transcriptions.layer = 'auto')
   ↓
النص المصحح يدويًا   (transcriptions.layer = 'manual')
   ↓
الترجمة العربية      (translations → target_lang='ar')
```

كل طبقة صف مستقل في قاعدتها؛ التصحيح لا يمحو النص الآلي، والترجمة لا تحل محل النص الأصلي.

### 8.2 حالات سير العمل الخمس (تظهر للزائر بشارة واضحة)

| الحالة | المعنى | تُخزن في |
|---|---|---|
| غير مترجمة | لا توجد ترجمة بعد | `translation_status='none'` (لا صف في `translations`) |
| ترجمة آلية | مولّدة آليًا، غير موثوقة كنص نهائي | `status='machine'` |
| ترجمة قيد المراجعة | بشرية قيد التدقيق | `status='in_review'` |
| ترجمة مراجعة | راجعها بشر | `status='reviewed'` |
| ترجمة معتمدة | نهائية معتمدة | `status='approved'` |

مثال الشارة: «حالة الترجمة: ترجمة مراجعة بشريًا». **لا تُنشر الترجمة الآلية على أنها نهائية أبدًا.**

### 8.3 القاموس المتخصص

جدول `glossary` (term_orig ↔ term_ar + domain) يُغذّي الترجمة بسياق تاريخ تشاد لا الترجمة العامة:

- Ouaddaï ←→ وداي، Abéché ←→ أبشة، Fort-Lamy ←→ فورت لامي
- Affaires musulmanes ←→ الشؤون الإسلامية، Commandant de cercle ←→ قائد الدائرة

لوحة الإدارة تتيح تعديل المداخل وإضافة مصطلحات جديدة؛ والواجهة العامة تعرض بحث القاموس عبر `GET /api/v1/glossary?term=`.

### 8.4 العرض جنبًا إلى جنب

صفحة المادة تعرض «النص الأصلي | الترجمة العربية» في عمودين متوازيين، مع شارة الحالة فوق الترجمة.

## 9. إدارة نسخ الصور

### 9.1 الأنواع الستة (عمود `version_type`)

| النوع | المعنى |
|---|---|
| `original` | الملف كما ورد من المصدر — لا يُمس |
| `restored` | ترميم: إزالة التلف والخدوش وتحسين الوضوح |
| `enhanced` | تحسين: الدقة والوضوح دون إزالة تلف |
| `colorized` | تلوين تقديري |
| `annotated` | نسخة مشروحة (علامات/تحديدات/شروح) |
| `cropped` | قصّ |

### 9.2 المقارنة قبل/بعد

أداة منزلق `<input type=range>` فوق صورتين متراكبتين (CSS `clip-path`) — التنفيذ في `public/app.js`. تحتها **بيان إلزامي**:

- للمرمم: «النسخة المرممة مشتقة من الصورة الأصلية. أزيلت منها آثار التلف والخدوش وحُسنت درجة الوضوح دون تغيير العناصر الأساسية للمشهد.»
- للملوّن: «التلوين تقديري ولا يمثل دليلًا قطعيًا على الألوان التاريخية الأصلية.»

يُخزن نص البيان في `image_versions.process_note` ويُعرض حرفيًا.

### 9.3 بيانات المعالجة الإلزامية

عند تسجيل أي نسخة مشتقة عبر `POST /api/v1/admin/materials/:id/versions` يجب: `fileId` + `versionType` (≠ original ما لم يكن الملف مرفوعًا كأصل) + `processNote`. التحقق يتم في `admin-api`.

### 9.4 حماية الأصل (§15 من التصور)

- لا يُسمح باستبدال ملف أصلي بنسخة معدلة — المفتاح في R2 لا يُكتب فوقه أبدًا.
- الأصل محفوظ باسم مستقل يتضمن بصمته (`<sha8>-<safe-name>`)، وتاريخ رفعه ومصدره وبصمته `sha256` مسجلة في جدول `files`.
- كل المشتقات مرتبطة بالأصل عبر `material_id` بوصفها مشتقات، لا بدائل.
- تدفق الرفع في الإدارة يسأل أولًا: «هل هذه الصورة أصلية أم نسخة مشتقة؟» — أصلية ← إنشاء مادة جديدة؛ مشتقة ← اختيار الأصل المرتبط ثم تحديد نوع المعالجة.

## 10. الصلاحيات والأمن

| المجال | المواصفة |
|---|---|
| المصادقة | اسم مستخدم + كلمة مرور؛ التجزئة PBKDF2 فقط (100,000 تكرار عبر `crypto.subtle`) بالصيغة `pbkdf2$100000$<b64salt>$<b64hash>` |
| الجلسات | جدول `sessions`؛ كوكي `archifouna_admin` بخصائص `HttpOnly; Path=/; SameSite=Lax; Max-Age=43200` (+`Secure` للإنتاج)؛ انتهاء بعد 12 ساعة |
| الأسرار | لا تُخزن في الكود؛ `ADMIN_PASSWORD_HASH` كـ secret (أو `.dev.vars` محليًا)؛ المدير الأول يُنشأ بسكربت `scripts/hash-password.js` + `wrangler d1 execute` |
| الرفع | حد 100MB (`MAX_UPLOAD`)؛ امتدادات مسموحة فقط: `pdf,doc,docx,jpg,jpeg,png,webp,tiff,tif`؛ الحفظ في R2 فقط؛ `Content-Type` صريح عند التقديم؛ منع تنفيذ الملفات المرفوعة |
| العزل | كل مسارات `/api/v1/admin/*` تتحقق من الجلسة داخل `routeAdminApi` (401 بلا جلسة)؛ مسارات `/admin/*` تتحقق قبل `renderAdmin` |
| التدقيق | كل عملية كتابة إدارية في `audit_log` (المستخدم، الإجراء، الهدف، التفاصيل، IP)؛ صفحة `/admin/audit` للمراجعة |
| النشر | المواد غير المنشورة (draft/hidden) تُعيد 404 للزوار؛ ملفاتها لا تُقدَّم عبر `/file/:id` العام |

## 11. لوحة الإدارة

عربية فقط (RTL). الصفحات: `/admin/login`، `/admin` (لوحة)، `/admin/materials`، `/admin/materials/new`، `/admin/materials/:id`، `/admin/people`، `/admin/places`، `/admin/sources`، `/admin/tags`، `/admin/collections`، `/admin/glossary`، `/admin/backup`، `/admin/audit`.

### 11.1 تدفق إضافة مادة

نموذج واحد يشمل: العنوان بالعربية، العنوان الأصلي، نوع المادة، التاريخ (+ مستوى الثقة)، المكان، اللغة، المؤلف/المصور، المصدر، المرجع الأرشيفي، الوصف، الكلمات المفتاحية، رفع الملفات، التفريغ، الترجمة — ثم **حفظ كمسودة** أو **نشر**. الإنشاء يولّد `ark` تلقائيًا ويعيد بناء فهرس البحث.

### 11.2 تدفق رفع صورة

1. السؤال الإلزامي: أصلية أم مشتقة؟
2. أصلية ← إنشاء مادة جديدة من نوع `image` + رفع الملف إلى `originals/images/{ark}/`.
3. مشتقة ← اختيار الصورة الأصلية ← تحديد نوع المعالجة (ترميم/تحسين/تلوين/تعليق/قص) ← كتابة بيان المعالجة ← تسجيل الصف في `image_versions`.

### 11.3 النسخ الاحتياطي من اللوحة

صفحة `/admin/backup`: زر تنزيل التفريغ JSON (`GET /api/v1/admin/export`) + قائمة الملفات (manifest) + تعليمات `wrangler d1 export` ومزامنة R2.

## 12. النسخ الاحتياطي ومبدأ الاستقلالية عن المزود

### 12.1 النسخ الاحتياطي (V1)

- **النسخة التشغيلية:** R2 + D1.
- **نسخة دورية** في `exports/backup-YYYY-MM-DD/`: تفريغ JSON كامل لقاعدة البيانات (`SIDJIL.json`) + `manifest.csv` (كل `r2_key` مع `sha256` والحجم) للتحقق من سلامة الملفات.
- لاحقًا: نسخة خارج Cloudflare (مؤجلة صراحة إلى ما بعد الاستقرار).

### 12.2 الاستقلالية عن المزود (مبدأ تصميمي ملزم)

- تصدير قاعدة البيانات ممكن دائمًا (`/api/v1/admin/export` + `wrangler d1 export`) — SQLite قياسي قابل للترحيل.
- كل الملفات قابلة للتنزيل من R2 بمفاتيحها المنظمة؛ الـ manifest يتيح التحقق من الاكتمال.
- لا ارتباط بمزود واحد يجعل النقل مستحيلًا: لا خدمات حصرية، والفهرس (FTS5) قابل لإعادة البناء برمجيًا عبر `rebuildSearchBlob` لأي مادة أو للدفعة الكاملة.
- الأرشيف مشروع طويل العمر، لا موقع مؤقت — كل طبقة قابلة للاستبدال دون فقدان البيانات.

## 14. النشر والتشغيل خطوة بخطوة

```bash
# 1) المتطلبات: Node.js + حساب Cloudflare + wrangler مسجّل الدخول
npm install -g wrangler   # أو npx wrangler

# 2) إنشاء الموارد
wrangler d1 create SIDJIL
wrangler r2 bucket create sidjil-assets

# 3) ربط الموارد في wrangler.toml
# [[d1_databases]] binding = "DB", database_id = "..."
# [[r2_buckets]]   binding = "FILES", bucket_name = "sidjil-assets"

# 4) تطبيق مخطط قاعدة البيانات
wrangler d1 migrations apply SIDJIL

# 5) إنشاء المدير الأول
node scripts/hash-password.js "كلمة-مرور-قوية"   # يطبع الهاش
wrangler secret put ADMIN_PASSWORD_HASH          # الصق الهاش
# (بديل: إدخال الصف مباشرة عبر wrangler d1 execute)

# 6) التطوير المحلي
wrangler dev   # مع .dev.vars للأسرار المحلية

# 7) النشر
wrangler deploy
```

ما بعد النشر: تسجيل الدخول إلى `/admin/login`، إنشاء مادة تجريبية، التحقق من البحث والترقيم والرفع، ثم تفعيل النسخ الاحتياطي الدوري.

## 15. خارطة الطريق

### 15.1 المرحلة الثانية (بعد استقرار الأرشيف)

- OCR للفرنسية ثم OCR للعربية (يغذي طبقة `transcriptions.layer='auto'`).
- ترجمة بالذكاء الاصطناعي (تغذي `status='machine'` مع بقاء المراجعة البشرية إلزامية قبل الترقية).
- قاموس تاريخي تشادي موسّع (توسعة جدول `glossary`).
- التعرّف على أسماء الأماكن والشخصيات (اقتراح روابط `material_people`/`material_places`).
- خرائط تفاعلية (استغلال `lat`/`lng` في `places`)، خط زمني (استغلال `year`).
- تصدير الاستشهادات بصيغ أكاديمية، API للباحثين، مجموعات خاصة بالموضوعات، حسابات مساهمين.

### 15.2 المرحلة الثالثة (منصة بحثية متقدمة)

- **خريطة تاريخية:** اختيار «أبشة» يعرض كل الصور والوثائق والخرائط المرتبطة بها عبر الزمن.
- **خط زمني تفاعلي:** 1800 ← 1850 ← 1900 ← 1950 ← 2000 لاستكشاف المواد حسب الفترة.
- **صفحات الأشخاص:** مثل «السلطان دود مرة» تجمع الوثائق والصور والكتب والأماكن والشخصيات ذات الصلة.
- **صفحات المؤسسات:** مثل «Collège Franco-Arabe d'Abéché» تجمع تاريخ المؤسسة وموادها.

البنية الحالية (جداول `people`/`places`/`material_*` وحقول الثقة والزمن) صُممت مسبقًا لاستيعاب هذه المراحل دون تغيير المخطط.

## الملحق: المبادئ العلمية الملزمة للتنفيذ

1. **الأصل لا يُمس** — الوثيقة الأصلية محفوظة دائمًا كما وردت من المصدر (R2 + `sha256`).
2. **المشتق يُعرَّف بوضوح** — أي ترميم/ترجمة/تلوين/تفريغ مشار إليه صراحة مع بيان ظاهر.
3. **المصدر مقدَّم على الادعاء** — حقل المصدر إلزامي قدر الإمكان (المؤسسة، المجموعة، رقم الحفظ، الرابط، تاريخ الاطلاع).
4. **عدم الجزم فيما هو محتمل** — حقول الثقة (`date_confidence`، `place_confidence`، `identity_confidence`: مؤكد/تقريبي/مرجح/محتمل/غير معروف) تمنع تقديم الافتراضات كحقائق.
