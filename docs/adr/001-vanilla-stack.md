# ADR-001: الإبقاء على البنية Vanilla (بلا أطر عمل)

- **الحالة:** معتمد
- **التاريخ:** 2026-10-01
- **صاحب القرار:** يعقوب عبدالله (مالك المشروع)

## السياق

البند §4 من «المواصفات التقنية التنفيذية» اقترح بنية قائمة على:
Astro + TypeScript + Tailwind CSS + Hono + Zod + Cloudflare Access.

في المقابل، نُفّذ المشروع فعليًا ببنية أبسط:
**Vanilla HTML/CSS/JavaScript + Cloudflare Workers + D1 + R2**،
مع جلسات PBKDF2 عبر WebCrypto للمصادقة الإدارية — التزامًا بتعليم سابق
صريح من مالك المشروع («بلا أطر عمل خارجية»).

## القرار

يُعتمد البناء الحالي نهائيًا، ولا يُعاد بناء المشروع باستخدام
Astro أو Tailwind أو Hono أو أي إطار آخر. يُعتبر البند §4 من المواصفات
**اقتراحًا تقنيًا غير ملزم**، والمعيار الحاكم هو تحقيق الوظائف والمعايير
المنهجية والأمنية والأدائية، لا استخدام إطار بعينه.

## السبب

1. **تقليل التعقيد والاعتماديات:** البناء الحالي بلا خطوة بناء (no build step)،
   وبلا اعتماديات npm للإنتاج — ما يقلل سطح الهجوم ويسهّل الصيانة طويلة الأمد.
2. **استقرار مثبت:** المنصة اجتازت معايير القبول العشرين كاملة على البناء الحالي.
3. **لا حاجة وظيفية مفقودة:** كل متطلبات MVP (الأرقام الثابتة، الطبقات، البحث
   المتقاطع، PDF.js كمكتبة وظيفية، تجريد OCR، CSRF/Rate Limiting) تحققت
   دون أي إطار.

## البديل المرفوض

إعادة البناء على Astro + TypeScript + Tailwind + Hono + Zod + Cloudflare Access
كما اقترح §4 — رُفض لأنه Migration غير ضروري لمشروع مستقر يحقق متطلباته،
وكان سيُدخل تعقيدًا (build pipeline، اعتماديات، منحنى تعلم) دون مكسب وظيفي.

## الأثر

- يُحدَّث §4 من المواصفات ليميز بين «البنية المقترحة أصلًا» و«البنية المنفذة فعلًا».
- PDF.js تُستخدم **كمكتبة وظيفية فقط** (ملفا `pdf.min.mjs` و`pdf.worker.min.mjs`
  في `public/vendor/pdfjs/`) — لا تُعد إطار عمل ولا تخرق هذا القرار.
- يُمنع أي Refactor شامل أو Migration غير ضرورية ما دام البناء مستقرًا.

## إمكانية إعادة النظر

يمكن إعادة النظر في هذا القرار مستقبلًا إذا ظهرت حاجة مثبتة لا يحققها البناء
الحالي (مثل الحاجة إلى SSR معقد أو توليد صفحات ثابتة ضخمة)، وبقرار صريح
جديد من مالك المشروع — لا تلقائيًا.
