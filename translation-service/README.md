# sidjil-translation-service

خدمة داخلية لمعالجة ملفات PDF الثقيلة. ليست واجهة مستخدم عامة؛ يتصل بها Worker عبر `TRANSLATION_SERVICE_URL` وتتحقق من `TRANSLATION_SERVICE_TOKEN`.

## التشغيل

1. انسخ `.env.example` إلى `.env` وضع عنوان Worker والرمز السري نفسه في Worker. لا تحتاج الخدمة إلى مفاتيح R2؛ يمرر Worker ملفات الإدخال ويستقبل ملفات الإخراج عبر مسارات داخلية محمية.
2. ثبّت النموذج مرة واحدة على Windows: `ollama pull qwen3:8b` ثم تحقق عبر `ollama list`. يجب أن يظهر الاسم والحجم قبل تشغيل الخدمة.
3. شغّل `docker compose up -d --build`.
4. افحص الخدمة محليًا عبر `http://127.0.0.1:18080/health`، ثم endpoint المحرك المحمي `/engine`. اضبط `TRANSLATION_SERVICE_URL` و`TRANSLATION_SERVICE_TOKEN` كأسرار Worker، واضبط `OLLAMA_BASE_URL=http://host.docker.internal:11434` و`OLLAMA_MODEL=qwen3:8b` داخل ملف `.env` الخاص بالخدمة.

في بيئة Sidjil الحالية، العنوان العام للخدمة هو `https://translate-api.sidjil.org`، ويُدار عبر Tunnel مُسمّى إلى المنفذ المحلي `18080`. لا تضع المنفذ المحلي في `TRANSLATION_SERVICE_URL`؛ استخدم عنوان HTTPS العام.

يبقى النموذج محملًا أثناء دفعة الترجمة بواسطة `OLLAMA_KEEP_ALIVE=10m`، وتُحدَّد الترجمة الثقيلة بعملية واحدة عبر `MAX_AI_TRANSLATION_JOBS=1`. اختبر المسارات `fr↔ar` و`en↔ar` و`fr↔en` عبر `/translate` أو Worker. بيانات volume القديم محفوظة ولا تُحذف تلقائيًا.

الخدمة تستخدم `pypdf` لاستخراج النصوص، وOCRmyPDF/Tesseract للملفات الممسوحة، وOllama محليًا مع `qwen3:8b` للترجمة. تنتج `mode=text` ملفًا نصيًا مترجمًا، وتنتج `translated` و`bilingual` ملف PDF جديدًا منظمًا صفحةً بصفحة يحوي الترجمة أو النصين. هذا مولد PDF نصي محافظ على المحتوى؛ إعادة بناء التخطيط الأصلي مع وضع الترجمة فوقه تحتاج Adapter متخصصًا مثل PDFMathTranslate أو BabelDOC. لا تُعاد نسخة الأصل على أنها مترجمة، ولا تُعرض خدمة Ollama للإنترنت مباشرة.

### تنسيق PDF العربي

ملفات PDF العربية تستخدم خط `IBM Plex Sans Arabic` نفسه المعتمد في واجهة سِجِل، ويُضمَّن الخط داخل الملف بعد تحويل نسخة WOFF2 الخاصة بالواجهة إلى صيغة PDF المناسبة. العناوين العربية تُبنى في فقرات منفصلة عن وسم `SIDJIL` اللاتيني حتى لا ينقلب ترتيب الكلمات، والنص العربي بمحاذاة كاملة (`justify`) مع تباعد أسطر وهوامش مناسبة للقراءة. عند إنتاج ملف ثنائي اللغة يُعرض النص الأصلي بترتيبه اللغوي، ثم الترجمة العربية باتجاه RTL.

يتيح العارض الحي أيضًا نقطة `/ocr` الداخلية للصفحات المصوّرة: يرسل العارض صورة الصفحة عند غياب النص القابل للاستخراج، ثم تمر نتيجة OCR إلى مسار الترجمة المعتاد. تبقى نقطة OCR محمية بالرمز الداخلي ولا تُعرض للعامة مباشرة.
